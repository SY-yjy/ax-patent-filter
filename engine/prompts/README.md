# prompts/ — 에이전트 지시문(프롬프트)

| 파일 | 언제 쓰이나 | 역할 |
|---|---|---|
| `추출.md` | 모든 건 | 원문 청구항에서 **판정에 필요한 사실만 구조화 추출**. 등급은 정하지 않음 |
| `스캔판독.md` | 스캔 이미지 PDF | PDF 페이지를 이미지로 읽어 **청구항 원문 전사**. 판정하지 않음 |

## ⚠️ 프롬프트가 등급을 정하지 않습니다

이 시스템에서 **AI는 라벨(노이즈/유효/이슈/보류)을 결정하지 않습니다.**

```
AI 추출 (프롬프트)  →  사실만:  flags / choices / properties / 근거인용
       ↓
규칙 엔진 (rules.py + tasks/*.yaml)  →  등급 확정
```

이렇게 나눈 이유는 **재현성**입니다. LLM이 라벨을 자유롭게 정하면 같은 특허도 실행마다
결과가 달라질 수 있습니다. 추출값이 같으면 등급은 항상 같습니다.

그러므로 **프롬프트에 "이런 건 이슈다" 같은 판정 규칙을 넣지 마세요.** 그건
`tasks/*.yaml` 의 `rules` 에 씁니다. 프롬프트는 *어떻게 원문을 읽고 사실을 뽑는가*만 다룹니다.

## 3값 원칙이 핵심입니다

`추출.md` 는 모든 flag를 `yes` / `no` / `unclear` 로 답하게 합니다. `unclear` 는 실패가
아니라 정확한 답이고, 규칙 엔진이 그걸 **보류**로 보내 사람에게 넘깁니다.
"애매한 걸 억지로 분류하지 않는다"는 IP전략팀 피드백이 이 한 줄로 구현됩니다.

## 문서 확인 우선순위

`추출.md` 는 이 순서를 강제합니다: **독립청구항 → 종속청구항 → 과제·효과 → 실시예 →
평가결과 → 초록 → 제목.** 실시예가 무엇이든 **독립청구항이 무엇으로 한정되어 있는지**가
기준입니다("실시예가 에폭시니까 이슈 아니다" 금지).

## 고치는 법
1. `.md` 파일을 수정하고 저장한다.
2. 앱/파이프라인을 다시 실행하면 반영된다.

> 실행마다 `output/runs/<회차>_<시각>/meta.json` 에 **프롬프트 전문 + 과제 yaml 전체**가
> 스냅샷으로 저장됩니다. 결과가 달라졌으면 두 실행의 `meta.json` 을 비교하세요.

## 판정 지시는 세 겹

| 무엇 | 어디 |
|---|---|
| 원문을 어떻게 읽고 사실을 뽑나 | `prompts/추출.md` (과제 무관) |
| 무엇을 추출하나 · 무엇이 노이즈/유효/이슈/보류인가 | `tasks/*.yaml` (과제별) |
| 모델·백엔드·상한·스캔판독 on/off | `config.yaml` |
